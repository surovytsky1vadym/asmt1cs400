What was generated, per part of the work, and what was changed
--------------------------------------------------------------
Every commit on the stage3 branch was written by the agent. The generated
code was not edited by hand.

1. Loops (commit "feature: while and for loops ...")
   Tokens 🔁 🏃 🛑 ⏩ in kagu/lexer.py, WhileNode / ForNode / BreakNode in
   kagu/nodes.py, two parser methods, the checks in kagu/semantic.py
   (bool condition, integer range, loop variable is a constant, 🛑 only
   inside a loop, a scope for the loop variable and one for the body) and
   the lowering in kagu/codegen.py (cond / body / step / end blocks, a back
   edge, a stack of loop exits for 🛑). Generated by the agent; taken as it
   was. One change while writing it: the agent's first edit of the
   assignment check left an empty branch for the loop variable; it was
   replaced by the error "cannot assign to loop variable" before the
   commit.

2. Loop tests
   tests/valid/loops_ast, tests/run/loops_while, loops_for_nested,
   loops_break and six tests/invalid/loops_*. Generated by the agent. The
   expected outputs were worked out by hand first (Collatz of 27 is 111
   steps, the multiplication table, the break pattern) and match what the
   compiled programs print. The invalid expectations are the compiler's
   own messages, checked to name the right line and rule.

3. Optimizer (commit "optimizer: ...")
   kagu/optimizer.py, the --optimize flag in compiler.py and the
   optimizer / programs sections of run_tests.sh. Generated by the agent.
   Two bugs were found by the optimizer tests and fixed before the
   commit: (a) inlining a call at the top level inserted the new
   statements into a temporary list, so the result name was "not
   declared"; (b) "z = z + x" counted as a read of z, so z was never
   removed. After the fix, z's own reads in a value assigned to z do not
   count.

4. Optimizer tests (tests/optimizer/)
   Six programs, two per transformation. Generated by the agent; the .ast
   files are the compiler's output after checking each tree by eye (what
   was removed, what was renamed, what was left alone), and the expected
   outputs are the same with and without --optimize (the runner checks
   both). Two test sources were changed because KaguLang writes a negative
   literal with ➖, not "-". The whole suite also passes with
   "run_tests.sh --optimize".

5. The program (programs/arena.txt, commit "program: ...")
   Generated by the agent. One change: the random generator first used
   💎64, which the language cannot narrow back to 💎32 for damage, so it
   was changed to 💎32. The three sessions were recorded from the built
   program and read through to check they make sense (session 1 wins,
   session 2 falls in wave 4, session 3 hesitates and runs away).

6. grammar.ebnf and README.md
   Generated by the agent: the loop rules (27–32) with passing and failing
   tests, two example programs, the IR excerpt of a while loop with the
   explanation of its blocks and the back edge, the optimizer section with
   the inlined / not inlined shapes and the before / after IR of inlining,
   and the program section with the llc + clang commands. llc was not
   installed; the agent installed LLVM with Homebrew, found that llc
   produced x86_64 code (my Python runs under Rosetta and the module
   carries its triple) and added -mtriple with clang's own triple to the
   README command; the program built that way passes all three sessions.

7. This file (ai_usage_3.txt)
   Drafted by the agent with my prompts copied as I sent them. The
   section "What I understood" below is written by me.
